# Büffel

Local-only spaced-repetition learning app (Kotlin Multiplatform). All logic lives in `shared/`; `androidApp/` (Compose) and `iosApp/` (SwiftUI) only render state and forward input. Learning content comes from packs in the open format specified in `format/`. The README has the overview, build steps and release process.

## Commands

```bash
source ~/.sdkman/bin/sdkman-init.sh && export ANDROID_HOME=~/android-sdk

./gradlew androidApp:assembleDebug
./gradlew shared:allTests androidApp:testDebugUnitTest      # on Linux the iOS test targets are skipped
./gradlew shared:ktlintCheck androidApp:ktlintCheck         # fix with shared:ktlintFormat androidApp:ktlintFormat
./gradlew androidApp:lintDebug
python3 format/validate.py --strict                         # needs jsonschema
```

CI runs the same (`android.yml`). Kover coverage (`shared:koverXmlReportDebug`) is informational only. Kotlin style comes from `.editorconfig` (ktlint official, 4 spaces, 140 columns).

## Modules

- **`shared/`**: pack reader, scheduler, planner, study session state machine, SQLDelight storage. `BueffelSdk` is the single entry point; `shared/README.md` is its reference, update it when the public API changes. Keep what the UIs do not need `internal`. No network code. On iOS it is the `shared` framework through SKIE. Kotlin is bumped only together with SKIE (Dependabot ignores Kotlin).
- **`androidApp/`**: Compose and Material 3, one package per feature under `ui/`. Unit tests in `androidUnitTest`.
- **`iosApp/`**: SwiftUI, project generated by XcodeGen from `iosApp/project.yml` (`*.xcodeproj` and `Bueffel/Info.plist` are generated and gitignored; add Info.plist keys in `project.yml`). **Views never `import shared`**: only `iosApp/Bueffel/SDK/` does. It maps shared types into the plain `Sendable` Swift models in `SDK/Models.swift`, and views use those.
- **`format/`**: the pack format, see below.

## Format contract

The spec in `format/` is a public contract. These change together, in one commit: `format/README.md` (spec), `bueffel-pack.schema.json`, `validate.py`, `test-vectors.json`, `AUTHORING.md`, `prompt.txt`, the examples, and the Kotlin reader in `shared/.../format/`.

- Run `python3 format/validate.py --strict` and `./gradlew shared:allTests` after any change.
- `validate.py` also checks that `format/README.md` embeds `examples/format-tour.bueffel` verbatim and that `AUTHORING.md` embeds `prompt.txt` verbatim: edit both copies.
- The `generateFormatResources` Gradle task compiles `format/examples/*.bueffel`, `prompt.txt` and `test-vectors.json` into the shared module (sample library, authoring prompt, conformance tests). Never edit the generated files under `shared/build/`.
- Additive changes keep `"version": 1`; anything breaking needs a new format version (spec section 14). Readers stay forgiving, writers strict.

## Strings

English and German, on both platforms, always both:

- Android: `androidApp/src/androidMain/res/values/strings.xml` and `values-de/strings.xml`. No hardcoded UI text (lint `HardcodedText` is an error). German uses Swiss spelling (ss, no eszett).
- iOS: `iosApp/Bueffel/en.lproj/Localizable.strings` and `de.lproj/Localizable.strings`, read through `L10n.tr/format/plural` (`Support/L10n.swift`; plural keys end in `.one` / `.other`).
- Errors and warnings from `shared` carry a stable `code`: localise the code in the UI, the English `message` is only a fallback.
- Labels must hold up in German (longer) and in dark mode.

## Both platforms

Every feature ships on Android and iOS. Implement both, or say in the commit message which one is deferred.

## iOS is compile-gated by CI

There is no Swift compile on Linux, and the iOS app has not been built yet. Do not try to compile Swift locally. Push, then read the iOS checks: `ios-build` first (shared framework plus simulator app build), then `ios-tests` (Kotlin/Native tests of `shared`); `ios-gate` is the always-reporting required check. After changing `shared/`, also check `shared:iosSimulatorArm64Test` results in CI, since Kotlin/Native can differ from the JVM (number formatting, time zones, `Instant.parse`).

Swift 6 language mode (`SWIFT_VERSION 6.0`), deployment target iOS 18. Check new Swift against these before pushing; a stricter toolchain than the one you assume may be the one that rejects it:

- Pure helpers on a `@MainActor` type (a `static` function or `static let` that only uses its arguments) are `nonisolated`, otherwise they cannot be called from synchronous or test contexts.
- Closure parameters that a `@MainActor` type runs are `@MainActor` themselves.
- There is no iOS test target yet. When one is added, tests that touch `@MainActor` APIs are `@MainActor` (the whole class when it has stored properties like `XCUIApplication()`).
- `SDKClient` is the one place with `@preconcurrency import shared` and `@unchecked Sendable`. Do not let shared (SKIE) types cross actors or reach views: map them to `Sendable` structs at the boundary.
- Split expressions the compiler cannot type-check in time (big heterogeneous literals, long `||` chains); that failure shows up only in CI.
- Grep before adding a constant or a string key: a duplicate (`L10n`) is only found by the CI build.

## SQLDelight

Tables are in `shared/src/commonMain/sqldelight/ch/orellbuehler/bueffel/db/*.sq`. `schemaOutputDirectory` is `shared/src/commonMain/sqldelight/databases/` (only `1.db` so far) and `verifyMigrations` is on. After changing a table, from the repo root:

```bash
./gradlew shared:generateCommonMainBueffelDatabaseSchema   # writes the snapshot of the current schema
./gradlew shared:verifyCommonMainBueffelDatabaseMigration  # migrations and CREATE statements must agree
```

Before a release has shipped the database, regenerate `1.db`. Once users have a database, never rewrite a shipped snapshot: add `<n>.sqm` (migration from snapshot n) next to the snapshots, generate the next snapshot and verify. CI does not run the verify task.

## CI and release

`android.yml` and `ios.yml` gate every PR; `release.yml` ships signed builds (secrets table in the README). Actions are pinned to commit SHAs with a version comment: keep that when bumping. Signing material (`*.jks`, `*.p12`, `*.mobileprovision`) is gitignored and must never be committed. `iosApp/ExportOptions.plist` has no team id (the workflow injects it) and its profile name `Bueffel App Store` must match the provisioning profile.

## Git

Commit style: lowercase imperative, short first line, details in the body if needed (e.g. `add pack detail screen`). Never add `Co-Authored-By` or any attribution line. Stage files by path, not with `git add -A`.
